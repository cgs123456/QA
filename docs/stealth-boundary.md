# 隐身边界（taskP7 / PRD §1.6）

> 本文档是**约束**，不是说明。它规定本仓在「窗口级增强」方向上**可以做**与
> **永远不做**的事。新增任何相关能力前，先在这里登记判定，再写代码。
>
> 代码位置：`src-tauri/src/stealth/`（`mod.rs` 头注释有同一份边界的简版）。

## 一句话

**只声明本应用自己窗口的显示属性；不对别人的程序或系统动手。**

## 1. 做：本仓已实现的能力

每一项都是**操作系统公开的窗口属性**，作用域仅限本应用自己的窗口。

| 能力 | 平台 | 实现 | 效果边界 |
|---|---|---|---|
| 无边框透明置顶窗 | 全平台 | `WebviewWindowBuilder::{decorations(false), transparent(true), always_on_top(true), skip_taskbar(true)}` | 只影响本应用窗口 |
| 不进屏幕捕获 | Windows | `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)` | 只对 DWM 捕获生效；**本人观看不受影响**；采集卡与部分远程桌面/虚拟机方案仍可能拍到 |
| 不进屏幕捕获 | macOS | `NSWindow.sharingType = .none`（经 tauri `content_protected(true)`） | 影响截屏与录屏；需 macOS 10.14+；**本机无 mac，未在真机验证** |
| 不进屏幕捕获 | Linux | **无等价 API** | 只做到置顶 + 透明；`get_overlay_status` 返回 `best_effort`，明示不保证 |
| 不抢焦点 | Windows 等 | `focusable(false)`（Windows 上对应 `WS_EX_NOACTIVATE`） | 不拦截鼠标消息，不影响后续做拖动 |
| 独立窗口 + 重建入口 | 全平台 | 独立 `WebviewWindow`（label `teleprompter`） | 提词窗销毁/崩溃不影响主应用；重建走同一段 `Plan::Create` |

判定标准：**「这是不是 OS 给我的、关于我自己窗口的一个属性？」** 是 → 可以做。

## 2. 不做：明确禁止清单

以下任何一项，**本仓不接受实现**，包括「只在 dev 分支」「只加个 feature flag」
「用户手动打开」这类变体。

| # | 禁止项 | 具体形态（含近义实现） | 为什么不做 |
|---|---|---|---|
| 1 | 进程伪装 | 改名冒充 `Zoom.exe` / `Teams.exe` / 系统进程；伪装窗口类名与标题；伪造数字签名 | 冒充别的程序是欺骗，且签名伪造违法 |
| 2 | 进程/模块名混淆 | 随机化 exe 名、内存中改名、卸载 PE 头 | 唯一目的是躲过别人的枚举，没有正当用途 |
| 3 | 反调试 | `IsDebuggerPresent` 探测、PEB 改写、`NtQueryInformationProcess` 反调试、`ptrace` 反附加 | 对抗调试器 = 对抗分析，是恶意软件特征 |
| 4 | 反检测 | 探测虚拟机/沙箱/录屏软件/屏幕共享状态并改变行为 | 一旦「检测到被录就藏」，本工具就从辅助变成作弊 |
| 5 | 监考/录屏绕过 | 针对 Zoom、腾讯会议、飞书、ProctorU、Respondus LockDown、Honorlock 等做对抗；检测到就隐藏、或注入其进程 | **直接越过 PRD §1.6 红线**。这是「考试作弊工具」，不是本地提词器 |
| 6 | 注入其它进程 | DLL 注入、`CreateRemoteThread`、API hook、`SetWindowsHookEx` 全局钩子、输入法/IME 注入 | 对别人的进程动手；且会破坏对方稳定性 |
| 7 | 内核层手段 | 驱动、内核回调、`ObRegisterCallbacks`、过滤驱动 | 需签名与提权；一旦出错是蓝屏，不是崩溃 |
| 8 | 改别人的配置 | 修改其它软件的注册表/配置文件、改系统显示或 DPI 策略来骗过捕获 | 影响用户其它软件，且难以卸载干净 |
| 9 | 超范围键盘记录 | 记录本应用注册的全局快捷键以外的按键（含全局钩子键盘记录） | 键盘记录本身就是恶意行为 |
| 10 | 绕过系统安全策略 | 绕过 UAC、关闭杀软、改组策略来让自启生效 | 用「绕过」代替「告诉用户为什么不行」 |

判定标准：**「这是不是在对别人的程序或系统动手？」** 是 → 不做。

## 3. 为什么把线画在这里

1. **合规**。第 5 项那一类手段在面试与考试场景下属于作弊工具。交付它，
   产品定位就从「本地优先的辅助工具」变成「对抗工具」，性质不同。
2. **技术**。第 6–10 项都要提权、驱动签名、杀软对抗。成本高、不稳定，
   任何一次系统更新都可能失效 —— 投入产出比是负的。
3. **信任**。本应用的核心承诺是「本地优先、内容不落日志」（R14）。
   一旦引入注入与 hook，「不上传、不记录」这个承诺就无法被审计了。

## 4. 诚实的边界：本仓**不**承诺什么

写清楚，是为了不让下面这些被当成 bug 报上来：

- **`WDA_EXCLUDEFROMCAPTURE` 不是「绝对拍不到」**。它只作用于 DWM 合成路径；
  硬件采集卡、部分远程桌面/虚拟机/虚拟摄像头方案在系统层绕过 DWM，仍可能拍到。
- **它只影响捕获，不影响本人观看**。窗口对使用者照常可见 —— 这正是我们要的：
  提词窗自己看不见就没用了。**不要把它当 bug 修。**
- **Linux 不保证**。X11 没有等价属性；Wayland 下连「置顶」都由合成器决定。
  `get_overlay_status` 会如实返回 `best_effort`。
- **macOS 未在真机验证**。实现走的是 tauri 的 `content_protected`（tao 内部
  `sharingType = .none`），代码路径正确但本机无法实跑。
- **不承诺对任何特定软件「隐身」**。本仓只做上面表格里那几条窗口属性，
  不针对任何第三方软件做适配或对抗。

## 5. 变更纪律

1. 新增「窗口级」能力前，先在本文件登记它落在第 1 节还是第 2 节。
2. 落在第 2 节的，**不做**，也不做「先合进去再删」。
3. 第 1 节的能力，必须：有纯函数单测钉住决策、有人工验证清单条目
   （`docs/manual-verification-p7.md`）、并在本文件写清效果边界。
4. 平台的「做不到」必须如实上报（如 `CaptureExclusion::BestEffort`），
   **不许用偏门手段把它变成「看起来做到了」**。
