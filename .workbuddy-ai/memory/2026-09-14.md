1. `SyncSender` 无法实现"满则丢弃最旧"——生产端不能驱逐队首，`try_send` 只能拒最新。
   凡 R13 类要求（有界 + 丢最旧 + 永不阻塞），std mpsc 不可用，需自建有界队列。
   落地为 `DropOldestQueue<T>`（帧与事件两条通道共用）。
2. rubato 5 的适配器 API：`InterleavedSlice::new` / `new_mut` 是**同一个类型**的两种构造，
   没有 `InterleavedSliceMut`；`Indexing` 在 `rubato::Indexing`，不在 `audioadapter` 下。
   48k→16k `FixedSync::Output`：chunk in=1440 / out=480，延迟 240 输出帧（常量）。
3. wasapi 0.24：**设备回环**是 `device.get_iaudioclient()` +
   `initialize_client(&fmt, &Direction::Capture, &EventsShared{autoconvert:true,..})`
   （渲染设备 + Capture 方向 → crate 自动加 LOOPBACK 标志）；
   `new_application_loopback_client` 是**进程回环**，不是设备回环，别用错。

**架构裁定**（已写进 PROGRESS.md 与代码文档）：

- 原生格式读取而非假设：wasapi 取 `Device::get_device_format()` 的 rate/channels，
  只强制 f32 容器 + autoconvert，重采样全留给 rubato。
- cpal 数据回调只做 downmix + 入队；resampler 与帧队列由独立 pump 线程持有。
  `cpal::Stream` 是 `!Send`，必须全程留在创建它的线程。
- `ts_ms = 帧序号 × 30`（样本计数派生），seq 每帧自增 → 10 分钟漂移是构造性质。
  设备切换只 `set_input_rate` 换 resampler，seq/ts 不重启。
- `start()` 经一次性 channel 同步返回启动结果（失败快速失败），会话中途失败才退避重试。

## 1b-4 vad.rs（VAD 抽象层，仅第 1 步）

**产出**：`src-tauri/src/audio/vad.rs`（`Vad` trait + `WebrtcVad` + `SileroVad` stub

**关键参数（记录在案）**：aggressiveness 初值 `2`（libfvad mode 2 = Aggressive）；
30ms/480 samples/16kHz 用 `const _: () = assert!(...)` 在编译期钉死。

**webrtc-vad 0.4.0 的真实 API（与文档假设不同，实测）**：
- 它包的是 **libfvad**，不是 Google WebRTC VAD 本体。
- `Vad::new()` 默认 **8 kHz / Quality**；正确构造是
  `Vad::new_with_rate_and_mode(SampleRate::Rate16kHz, VadMode::Aggressive)`。
- 方法名是 `is_voice_segment(&mut self, &[i16]) -> Result<bool, ()>`（注意是 `&mut self`）。
- `VadMode` **没有** derive `Copy`/`Clone`，不能存字段后重复用 → 存 `u8` 现算。
- `Vad` 持裸 `*mut Fvad` → **`!Send`**，必须在使用它的线程里构造。

**两个静默失效入口（R19 所指的"已知音频兼容问题"）**：
1. 默认 8 kHz：480 samples 在 8 kHz 下是 60ms 帧 → `Err(())`。把 `Err` 当 `false` 就永久静音。
2. **更隐蔽**：`Vad::reset()` = `fvad_reset()` = `WebRtcVad_InitCore()` + `rate_idx = 0`，
   会把采样率打回 8 kHz、模式打回 0（`kDefaultMode = 0`）。分段状态机在段边界 reset 是
   自然动作 → 由**正常代码路径**触发同一静默失效。
   → `WebrtcVad::reset()` 后 `reapply_config()` 重新钉回 rate+mode。

**设计裁定**：`is_voiced` 返回 `Result`，绝不把 provider 错误折叠成 `false`（"判为静音"
与"未能判定"必须可区分）；`WebrtcVad::errors` 计数暴露该状态；trait 不要求 `Send`；
手写 `Debug` 避免裸指针进日志。

**合成样本实测**：speech-like 合成信号在 mode 0/1/2/3 **全部 100/100 voiced**，
纯静音 0/100 → 能证非退化，但**饱和到区分不出档位**，不能替代真实人声自测。

**验证**：`cargo test --lib` 48（audio 39，vad 新增 13）+ 集成 1；clippy 零警告；
rustfmt clean。踩到 `chunks_exact` 常量长度 clippy 告警 → 改 `as_chunks::<N>()`
（本仓库既有约定）。

## task-14 Rust→sidecar 音频 WS 全链路

**产出**：`src-tauri/src/audio/uplink.rs`（WS 客户端 + 下行→Tauri 事件桥）、
`src-tauri/tests/audio_ws_e2e.rs`（跨语言 e2e）、`scripts/serve_audio_e2e.py`
（真实 uvicorn 测试对端）；`sidecar/src/routers/audio.py` 段缓冲按 R13 改造；
`frame.rs` 加 `encode_ws_event`/`TYPE_EVENT`。

**查出两个既有致命问题（都不是本次引入）**：
1. **依赖/打包缺 WebSocket 实现 → `/audio/stream` 全挂**。`uvicorn ws="auto"` 在
   `websockets`/`wsproto` 都缺时**不降级**，对升级请求回 **404**。实测装 websockets 前
   三个用例全 404，装后 good-token 才 101。
   既有 pytest 全绿是因为 FastAPI `TestClient` 走**进程内 ASGI，绕过 uvicorn**。
   修：`pyproject.toml` + `requirements-lock.txt` 加 websockets；
   `sidecar/build.py` 加 `--collect-all websockets`（uvicorn 动态 import，
   PyInstaller 静态分析看不到 → 不 collect 则**打包产物照样 404**）。
2. **鉴权失败线上是 HTTP 403，不是 WS close 1008**。`accept` 之前 `close()` 在真实 ASGI
   上表现为握手失败（uvicorn 403）；1008 只在 TestClient 下可见。
   裁定**不改 sidecar**：accept 前拒绝是有意安全姿态 + RFC 6455 §4.1 允许；
   且 403 让客户端 fail-fast（connect 直接 Unauthorized），1008 只能连上后再关。
   客户端两种都认。DoD 字面「失败 1008」有偏差，已记 api-contract.md，待主人裁定。

**顺手修真 bug**：`audio_stream` 把正常断开（`websocket.disconnect` 消息）计入
`malformed`，每次正常结束虚增 1 → 现正常退出，文本帧仍计 malformed。

**R13 缓冲策略变更（1b-1 → task-14）**：32MB 自动封段 → **丢最旧帧 + dropped_oldest
计数 + 每段一次 `segment_truncated` 告警**，上限 `MAX_SEGMENT_FRAMES=2000`（60s）。

**Rust 设计裁定**：
- **wire seq 由 uplink 独占**（R10 音频/事件共享一个序号空间，两套计数器必然撞号）；
  在**入队时**打号 → 被 R13 丢的帧在对端表现为 seq 空洞（丢帧可见）。
  `Frame16k.seq` 降为采集侧生产者计数。
- 出站队列 `OUT_QUEUE_CAPACITY=128`，自建 mutex+deque+`Notify` 异步丢最旧队列
  （std/tokio mpsc 都只能拒最新）。`Notify` 存 permit，故无丢唤醒竞态。
- 下行经 `EventSink` trait 桥接（生产 `TauriSink`，测试记录型替身）→ 映射可无 Tauri 运行时测。
- 事件先本地校验（event/path/ts_ms/path 一致性），把对端 `violations` 变成即时 `UplinkError`。
- `UplinkConfig` 手写 `Debug` 脱敏 token。

**验证**：`cargo test` **71 passed**（lib 67，uplink 新增 19；集成 1；e2e 3）+
clippy 零告警 + rustfmt clean；`pytest` **124 passed**（audio 协议 13→17）。
